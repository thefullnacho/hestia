# BirdNET listening station — spec

Passive acoustic wildlife detection: a mic outside, a classifier identifying bird calls
24/7, detections landing in records as `sighting` events — the **acoustic twin of
[EYES_PLAN.md](EYES_PLAN.md)** (same classifier-first thesis: closed-set model,
confidence-scored, deterministic; no LLM in the loop). Plus the household-object half: an
e-ink display in the kitchen showing the week's yard birds.

Why now, not someday: the pest-watch bird-crew theory (PEST_WATCH.md / 2026 season log)
queues a **2027 bird-count vs pest-outcome correlation** — which needs a season of counts.
Manual sightings can't produce statistics; a listening station counts around the clock.
Every month without it is baseline data lost.

## Architecture (one new container, one bridge, zero GPU)

```
outdoor mic node ──RTSP──▶ BirdNET-Go (docker, hl-relay) ──MQTT──▶ bridge ──▶ records events
                                      │                                          │
                                      └── web dashboard (its own)                ├─▶ nightly journal / almanac / briefing
                                                                                 └─▶ /birds/week.png ──▶ e-ink display (Pi Zero)
```

- **BirdNET-Go** (`tphakala/birdnet-go`) runs on **hl-relay** — the analysis model is tiny
  (runs 24/7 on a Pi; the Dell laughs at it) and it belongs next to MQTT/HA like everything
  event-shaped. One RTSP source per instance. The Ti is not involved; Eyes keeps its headroom.
- **Mic node** is dumb and outdoors: it streams audio, nothing else. Options in Hardware below.
- **Bridge** (`brain/bird_bridge.py`, systemd user service on the GPU box or a script on
  hl-relay): subscribes to BirdNET-Go's MQTT detections, collapses + filters them (below),
  writes records events. Same shape as the reminders/journal timers — small, deterministic.

## The records line (differs from Eyes — deliberately)

Eyes is propose-only because a photo ID pre-fills a *human's* filing action. Acoustic
detections are different: the **counts are the product**, there are hundreds a day, and a
confirm-tap per chirp is absurd. So the line moves, but the mint-guard doesn't:

- **Known-roster species** (entity already exists in records): detections **auto-log** as
  `sighting` events, `attrs: {source: birdnet, confidence, n_detections, window}`. This is
  a deterministic closed-set classifier writing non-authoritative observation events —
  within the determinism north star, not an LLM judgment call.
- **Out-of-roster species**: NO auto-mint, ever. First detection of an unknown species files
  a proposal (`data/birds-inbox/`) with the audio clip path + confidence; the ⚠️new-entity
  confirm stays human, exactly like photo ingest. Confirmed once → future detections
  auto-log. (This is also the fun part: "Hestia heard something new today.")
- Confidence gate: start at **0.7**, tune per false-positive experience. Detections below
  the gate are counted in BirdNET-Go's own dashboard but never reach records.

### Counting methodology (the 2027 correlation depends on this)

BirdNET emits overlapping ~3 s window detections — raw detections ≠ birds. The bridge
collapses to **visits**: consecutive detections of the same species within a **5-minute
cooldown** = one `sighting` event (with `n_detections` preserved in attrs for later
re-analysis). The correlation unit is **species-day visit counts** — robust to a chatty
wren inflating raw numbers. Dawn chorus will dominate; that's fine, it's consistent
day-over-day, which is what a correlation needs. Document the gate + cooldown in the event
attrs so 2027-you knows exactly what a count meant.

## The display (the household-object half)

A kitchen e-ink panel showing the **week's yard birds**: species art, visit counts, a
first-heard-this-year badge, maybe a 7-day sparkline. Prior art exists for the concept
(listening device + in-home weekly-birds screen); ours rides the records data.

- **Server-side rendered**: the brain grows a `/birds/week.png` endpoint (Pillow composite,
  sized to the panel, regenerated by the nightly journal timer). The display device stays
  dumb — it pulls a PNG on a timer. All logic lives where the data lives.
- **Species art, deterministically**: one-time fetch per confirmed species (Wikimedia
  Commons) into `data/birds/art/<species>.jpg`, cached forever, composited locally. No
  generation, no per-render network dependency. A missing image renders as a text tile
  until the cache backfills.
- **Device**: the spare Pi Zero + a 7.3" e-ink panel (hardware below). E-ink is the right
  medium — a daily/6-hourly refresh of a static image is exactly what a Zero + e-ink does
  well, and it looks like a nature poster, not a gadget.
- Voice hook for free: the almanac/wildlife skills already trigger on species questions;
  sightings landing in records means "have we heard orioles yet this year?" just works.

## Hardware (buy list)

**Mic node — recommended: ESP32 + I2S MEMS (~$20–25).** The `esp32-birdnet-mic` project
(ESP32 XIAO + I2S MEMS mic) is purpose-built for BirdNET-Go: RTSP streams, OTA updates,
auto-recovery, HA MQTT discovery. Tiny, PoE-free (any USB PSU), fully outdoor-able in a
vented enclosure. No SD card to corrupt, no OS to patch — the right amount of computer.

**Mic node — audiophile alt (~$100–130):** Pi Zero 2 W + USB sound card + **Clippy/Primo
EM272** mic — the community-standard capsule; meaningfully better range and SNR. Defensible
upgrade *later* if the MEMS mic's detection radius disappoints; don't start here.

**Mic node — $0 scrappy validation:** the Pi 4 + M1 mic already on hand (idle since Voice
PE took over the satellite role), by a cracked window. Wrong long-term (weather, placement)
but perfect for Phase 0.

**Display (~$90–105):** Pimoroni **Inky Impression 7.3"** (7-color e-ink) + the spare
Pi Zero. ⚠️ CHECK THE ZERO: a Zero **W** (has WiFi) works; an original no-W Zero has no
network and needs replacing (Zero 2 W, ~$15). $0 alt: a "Yard birds" card on the HA
dashboard — ship this first regardless, the e-ink is the physical upgrade of the same PNG.

**Placement:** under an eave, pointed at the feeders/beds, away from the HVAC compressor
and road noise; windscreen/foam over the capsule. Wind and rain are the noise floor.

**Total: ~$115–130** (ESP32 node + panel), assuming the Zero is a W.

## Phases

**Phase 0 — validate with zero purchases.** BirdNET-Go container on hl-relay, Pi 4 + M1 mic
at a window (or USB mic straight into hl-relay if reach allows). A week of its own dashboard:
does the yard produce detections? What species, what confidence distribution? Calibrates the
gate before anything is bought or written. Ships the fun immediately — the dashboard alone
is a delight.

**Phase 1 — records bridge.** `bird_bridge.py`: MQTT → visit-collapse → auto-log roster
species / inbox unknowns. Seed the roster from the wildlife skill's known species. Journal
picks up sightings automatically (records is canonical). THIS starts the correlation clock.

**Phase 2 — outdoor node.** Order the ESP32 mic node, mount it properly, retire the window
mic. Re-check confidence distribution (should improve).

**Phase 3 — display.** `/birds/week.png` + HA card, then the e-ink panel. Nightly regen on
the existing 23:45 timer.

**Phase 4 (2027) — the experiment.** Bird visit counts × pest-watch outcomes, per season.
The almanac YoY machinery already lights up automatically.

## Failure modes

| Failure | Mitigation |
|---|---|
| False positives (mimics — a mockingbird "is" 20 species; distant lookalikes) | confidence gate + roster prior; mimic species flagged in attrs when detected same-window as their impressions; counts are relative day-over-day, so consistent bias mostly cancels |
| Wind/rain sessions flood low-quality detections | gate handles most; bridge adds a max-events/hour bound per species, drop-with-log |
| Mic node dies silently (the real killer for a season of data) | silence watchdog: no detections AND no audio-level heartbeat for N hours → ntfy alert (rides the existing watchdog topic); esp32-birdnet-mic has auto-recovery + MQTT telemetry natively |
| MQTT flood / hl-relay load | BirdNET-Go is designed for a Pi; bounded bridge queue; per the hl-relay perf incident, watch swap on first week |
| Out-of-roster junk species (unlikely-for-region IDs) | inbox is human-gated; BirdNET-Go supports location-based species filtering — set lat/lon so the model itself excludes implausible species |
| Wikimedia art fetch fails / ugly crop | cached once, text-tile fallback, manual override by dropping a file in `data/birds/art/` |

Explicit non-goals: no LLM anywhere in the detection path; no auto-minting entities; no
audio retention beyond BirdNET-Go's clip exports (it's a bird logger, not a surveillance
mic — worth saying out loud for the public repo); no second RTSP source until one works.
